# 看板实时同步：静默窗与禁区说明（DeepSeek 终审 2026-10-20《看板全栏目实时同步》R6）

## 一、两个"夜间窗口"并存，不是 bug，禁止对齐

| 机制 | 窗口 | 管什么 | 定义位置 |
|---|---|---|---|
| 看板 build 软静默 | [00:00, 06:00) Asia/Shanghai | 看板事件驱动构建（kanban_watchd 触发层） | `scripts/sync_balance.py` → `BUILD_SILENT_WINDOW = (0, 6)`（单点定义） |
| 登记本快车道禁区 | [23:30, 08:30) Asia/Shanghai | 邮箱登记本摄取（fastlane） | `hidden_files/scripts/fastlane_config.py` → `WINDOWS` |

两者是**两种机制、两个用途**：快车道管邮箱摄取（避免打扰孩子/家长睡眠时段处理登记本照片），
看板软静默管构建与 push 节奏。边界不一致是设计使然，**未来维护不得擅自"对齐"**；如确需变更，
必须重新报 DeepSeek 终审。

注：2026-10-20 并行工作流（B档真实时化，commit 528ceef）已将 `build_stats.py` 的原时段闸门
（原 §2.2 工作日 19:00–23:00/周末 09:00–23:00）完全删除（其 DeepSeek 终审 KB-STATS-AUTO §2.2 废止）。
本方案的软静默 [00:00,06:00) 落在守护进程触发层实现（`kanban_watchd.py` 的 `in_silent_window`），

## 二、事件驱动架构（方案 A）

- 守护进程：`scripts/kanban_watchd.py`（watchdog 库不可用时轮询 20s，仅 stat mtime/size）。
  - `hidden_files/积分记录.md` → `build_stats.py` + `sync_sections.py`
  - `hidden_files/规则手册.md` → `sync_sections.py`
  - **不监听 `data/*.json` 产物**（防自触发循环）。
  - Q4 澄清：徽章颁发台账即积分记录.md（`sync_sections.extract_badge_events` 解析 `sb.LEDGER`），
    无独立徽章台账文件，不得虚构监听路径。
- 存活保障：`scripts/daemon_guard.py`（cron 5m）：PID 判活 → 死亡则查 git 静默窗（300s）后拉起。
- 单例：PID 文件 `logs/kanban_watchd.pid` + flock `/tmp/kanban_watchd.lock`；build 侧
  `build_stats.py` 已有 `/tmp/build_stats.lock` 串行锁。
- 限流（取与关系）：防抖 45s + 连续 push 间隔 ≥60s + 5 分钟滑动窗口 push ≤2 次
  （以 git 实际 commit 计，跨进程精确）；守护进程触发的 push 另记 `logs/push_rate.log`（审计）。
- 幂等：`build_stats.py` 按"忽略 generated_at 后的语义内容"判变更，无语义变化不 commit，
  杜绝 push 风暴（见 `semantic_diff`；R3 单调性拦截同函数）。
